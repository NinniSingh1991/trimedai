# TriMedAI

Code and results for *TriMedAI: personalising the timing of caregiver escalation
in assistive care from wearable activity signals. A simulation study*.

Everything reported in the article is produced by this repository. One command
regenerates every number, table and figure in it.

## What this is, and what it is not

An assistive-care agent that infers a **continuous** model of the person it is
serving and uses it to decide **when** to summon a caregiver, not merely how to
communicate.

Activity context is recognised from real wearable inertial signals, from thirty
healthy volunteers, evaluated on nine subjects held out of training. **The care
process above it is simulated.** Severity, the rate at which a condition
develops, and the effect of an assistance action on it are generated by the
model in `triage_env.py` and were not observed on any patient. Nothing here is
evidence about clinical effectiveness, and the article says so in its title, its
abstract and its conclusion.

Three stages:

1. **Reward inference** — a particle filter over a continuous latent (a frailty
   and a preference weight per delivery channel), revised from the channel the
   person indicates they would have preferred and from whether the monitoring
   layer reports that their condition worsened.
2. **Policy learning** — the model implied by that posterior is solved by value
   iteration, warm-started, whenever the belief moves. Planning is risk-averse in
   the frailty direction, at the 0.75 quantile.
3. **Meta-initialisation** — a starting policy averaged over latents drawn from
   the prior. It is computed offline, uses no user's data and no user's reward,
   and its whole contribution is to protect a person during onboarding.

## Reproducing the article

```bash
pip install -r requirements.txt
python reproduce.py            # everything, roughly 70 minutes on four cores
python reproduce.py --quick    # reduced budget, a few minutes, for a smoke test
```

The Human Activity Recognition corpus is downloaded from the UCI Machine
Learning Repository on first run. The subject-wise partition supplied with it is
used unchanged: 21 subjects for training, 9 held out, no person in both.

## How performance is measured

Mean reward per interaction has an arbitrary origin, so a ratio to a reference is
not invariant: adding a constant to the reward changes every such ratio and no
ordering. Scores are therefore anchored at both ends,

```
S(method) = 100 * (R_method - R_floor) / (R_reference - R_floor)
```

where the **floor** selects uniformly among the six actions and the **reference**
is optimal for the criterion actually reported, the undiscounted long-run mean
reward, obtained by relative value iteration (`triage_env.solve_average`). The
floor scores 0, the reference scores 100, and nothing can exceed the reference.
Raw reward is reported beside the score, and **regret** against the same
reference is the primary endpoint.

## Headline numbers

30 seeds, 80 simulated users each, interactions 100–200.

| Method | Normalised score | Regret / 100 | Deteriorations / 100 | Call-outs / 100 |
|---|---|---|---|---|
| Floor policy (random) | 0.0 | 26.38 | 2.07 | 16.61 |
| Per-user bandit (UCB) | 26.9 | 19.29 | 2.48 | 9.95 |
| Per-user tabular Q-learning | 42.2 | 15.13 | 5.45 | 0.65 |
| CNN + population rule | 57.5 | 11.23 | 5.60 | 0.00 |
| Multi-criteria rule | 62.8 | 9.84 | 3.81 | 5.06 |
| RLHF (pooled feedback) | 80.2 | 5.20 | 0.29 | 9.03 |
| Fixed-threshold escalation rule | 82.5 | 4.58 | 0.00 | 10.24 |
| Posterior sampling | 91.8 | 2.14 | 0.20 | 8.93 |
| **TriMedAI** | **97.5** | **0.65** | **0.58** | **7.91** |
| QMDP (given a solved policy per type) | 97.6 | 0.55 | 0.28 | 8.77 |
| TriMedAI, latent given | 98.1 | 0.46 | 0.58 | 7.91 |
| Reference policy | 100.0 | 0.00 | 0.15 | 8.81 |

TriMedAI and QMDP are tied on reward (p = 0.73), and QMDP is given an exactly
solved policy for each of the four named latent settings while TriMedAI is given
only the model class. **TriMedAI is not the safest policy here**: the reference
allows 0.15 deteriorations per 100 interactions and TriMedAI allows 0.58. That
gap is caused by the planning discount, not by the inference — a variant handed
the true latent and planning at the same discount also allows 0.58 — and
`frontier.py` traces the curve the discount moves along:

| Planning discount | Score | Call-outs / 100 | Deteriorations / 100 |
|---|---|---|---|
| 0.70 | 88.7 | 4.69 | 2.39 |
| 0.90 | 97.5 | 7.92 | 0.57 |
| 0.98 | 97.9 | 8.68 | 0.29 |
| 0.995 | 97.9 | 8.76 | 0.25 |

## Comparators

All twelve are specified in Table 10 of the article and implemented here. The
per-user bandit uses UCB with an exploration constant of 0.5; the per-user
Q-learner uses a learning rate of 0.25, a discount of 0.90 and epsilon decaying
from 0.15 to zero over the first hundred interactions; the pooled-feedback
policy is tabular Q-learning over 60,000 interactions with epsilon 0.2 and the
user resampled every 60 interactions; the multi-criteria rule weights channel
fit, context urgency and severity at 0.45, 0.35 and 0.20; the generative
baseline samples from a softmax with inverse temperature 3.0; QMDP and posterior
sampling project the continuous posterior onto the four named settings by a
likelihood proportional to `exp(-8 d)`.

## Layout

```
src/          environment, agents, experiments, figure scripts
data/         the corpus, downloaded on first run; not committed
results/      the JSON written by each experiment
figures/      every figure in the article
reproduce.py  one command to regenerate all of the above
```

`src/paths.py` is the single place that decides where those directories are, so
the scripts do not derive paths from their own location.

## Notes on the code

- `triage_env.py` defines the care process. `model_for()` and `plan()` express it
  for an arbitrary continuous latent and agree with the exact solver to 2.8e-17.
  `solve_average()` is the reference policy; `plan_average()` is the relative
  value iteration behind it.
- `triage_agents.py` holds the particle filter, the planner, the three
  backup-rule variants used in the ablation, and the comparators.
- `misspec.py` builds a `World` whose deterioration law, preference model and
  post-alert relief can each be replaced by something the agent cannot express.
  The reference and the floor are rebuilt on the true dynamics in every case, so
  the ceiling is correct while the agent is wrong.
- Seeds are fixed in each experiment script and every result file records the
  budget it was produced with.
