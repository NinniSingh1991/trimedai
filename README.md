# TriMedAI

Code and results for *TriMedAI, a framework for personalising the timing of caregiver escalation in assistive care from wearable activity signals. A simulation study* (Expert Systems with Applications, under review, ESWA-D-26-33960).

Every number, table and figure in the article is produced by this repository, and one command regenerates all of them.

## Scope

TriMedAI decides when an assistive system should alert a caregiver and tailors that decision to each person. Activity context is recognised from real wearable recordings. **The care process above it is simulated:** severity, the rate at which a condition develops and the effect of each action are generated by the model in `src/triage_env.py` and were not observed on any patient. No result in this repository is evidence of clinical effectiveness.

The framework has three stages and an optional safeguard:

1. **Reward inference.** A particle filter of 256 particles over a continuous latent (a frailty and a weight for each delivery channel), revised from the channel the person states they would have preferred and from the deterioration report of the monitoring layer.
2. **Policy computation.** The decision process implied by the posterior is solved by value iteration every 10 interactions, planning at the upper 0.75 quantile of the frailty posterior.
3. **Meta-initialisation.** An initial value table averaged over 24 latents drawn from the prior, computed offline from no user's data.
4. **Safety backstop.** A caregiver alert is forced whenever severity reaches band 2, the band at which the fixed-threshold rule escalates.

## Reproducing the article

```bash
pip install -r requirements.txt
python reproduce.py            # published budget, 30 seeds in every experiment; about 20 hours on a 14-thread laptop CPU
python reproduce.py --quick    # 3 seeds, 20 users, 3 recogniser seeds: a smoke test of the whole pipeline
```

`reproduce.py` runs the scripts below in order. Each script can also be run on its own from `src/`. The environment variables `N_SEEDS`, `N_USERS` and `TRAIN_SEEDS` (for example `0-29`) override the budget.

| Script | Produces | Article |
|---|---|---|
| `get_har.py` | UCI HAR corpus, downloaded and cached in `data/` | Section 4.1 |
| `get_external.py` | HAR70+, HARTH and KU-HAR, downloaded and unpacked in `external/` | Section 4.1 |
| `run_main.py` | `har_results.json`: main comparison, stage ablation, backup-rule ablation, safety backstop | Tables 4, 5; Figures S2, S3 |
| `run_extended.py` | `har_extended.json`: named and held-out latent settings | Table 6; Table S5; Figures S4, S5 |
| `onboarding_check.py` | `har_onboarding.json`: effect of the meta-initialisation by window | Table 5, panel C |
| `triage_curves.py` | `har_curves.json`: learning curves | Figure 3 |
| `frontier.py` | `har_frontier.json`: operating curve over the planning discount | Figure 5; Figure S1 |
| `thresholds30.py` | `har_thresholds.json`: deteriorations under fixed escalation thresholds | Figure 2 |
| `run_sweep30.py` (uses `sensitivity.py`) | `sens30_row0.json` to `sens30_row5.json`: 30-cell sensitivity sweep | Table 6; Table S6 |
| `misspec.py` | `har_misspec.json`: misspecified simulator and noisy deterioration report | Table 6; Table S8; Figures 6, S6, S7 |
| `continuous_population.py` | `har_continuous.json`: 1,800 people with continuous latents, with paired tests | Table 6 |
| `e1_older_adults.py` | `e1_recognition.json`, `e1_predictions.npz`: recognition on HAR70+ | Table 7; Table S4 |
| `e1h_harth_control.py` | `e1h_harth_control.json`, `e1h_predictions.npz`: age versus device and setting | Table 7 |
| `e4_more_subjects.py` | `e4_more_subjects.json`, `e4_predictions.npz`: recognition on 110 people | Table 7 |
| `e1d_decision_layer.py <condition> <mix>` | `e1d_*.json`: decision layer under each recogniser | Table 7; Table S7 |
| `e3_latency_load.py` | `e3_latency_load.json`: decision latency for 1 to 10,000 users | Table 8 |
| `compile_results.py` | `RESULTS_SUMMARY.md`: every number, read from the result files | All results |
| `make_figures.py` | `figures/*.png` | Figures 1 to 6; Figures S1 to S7 |
## Data

| Corpus | People | Sensor | Source and licence |
|---|---|---|---|
| UCI HAR | 30 adults aged 19 to 48 | waist-mounted smartphone, 9 channels at 50 Hz | Reyes-Ortiz et al. (2016); UCI Machine Learning Repository |
| HAR70+ | 18 adults aged 70 to 95 | lower-back accelerometer | Ustad et al. (2023), https://doi.org/10.3390/s23052368; UCI dataset 780, CC BY 4.0 |
| HARTH | 22 adults aged 25 to 68 | the same sensor and protocol as HAR70+ | Logacjov et al. (2021), https://doi.org/10.3390/s21237853; UCI dataset 779, CC BY 4.0 |
| KU-HAR | 80 of 90 adults with the six activities | smartphone in a waist bag | Sikder & Nahid (2021), https://doi.org/10.1016/j.patrec.2021.02.024; Mendeley Data 10.17632/45f952y38r.5, CC BY 4.0 |

## Repository layout

- `src/`: the simulator, the three stages, every comparator and every experiment script.
- `results/`: the result files behind every number in the article, at 30 seeds.
- `figures/`: every figure, regenerated from `results/` by `make_figures.py`.

## Environment

All results were produced on an Intel Core Ultra 5 125U processor with 15.5 GB of memory and no hardware accelerator, under Windows 11, with Python 3.12.10 and the versions pinned in `requirements.txt`.
